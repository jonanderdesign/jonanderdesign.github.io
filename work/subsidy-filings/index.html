Subsidy Filings.

How companies in Spain claim back part of their training costs: from paperwork prepared by hand to a flow inside Factorial.

Overview

Company
Factorial, HR software
Team
Me as the only designer, the engineering manager and the training team’s engineers
When
June to August 2026, live on 27 August
Result
158 filings from 22 companies in its first 11 weeks, outside the beta

Screens use invented data.

The problem

Companies in Spain can recover part of what they spend on training through FUNDAE, the state training foundation, but only if they make three kinds of filing on time for every course: one for the course, one when each group starts, and one when each group ends.

The three are spread over months: the last one only comes once a group has finished.

Factorial held the course data, but its old export only produced the last of the three. HR teams prepared the rest by hand, outside the product. Every filing is an XML file that FUNDAE checks against its own schemas.

  1. The courseFiled once, when the course is set up
  2. →
  3. Each group startsFiled again for every group
  4. →
  5. Each group endsWhen the group finishes, with costs and participants. The only one the old export produced

The key idea

The product cannot see FUNDAE’s portal. HR downloads the file from Factorial and uploads it there by hand, sometimes on another day. So generating a file cannot mean it has been filed.

I first treated the two as one step, then split them: HR downloads the file, and uses Mark as communicated once it is actually filed. Otherwise the product would show a filing as done when it is not. The cost is that the status depends on HR marking it (the product cannot check the portal).

  1. GenerateFactorial builds the XML
  2. →
  3. DownloadHR saves the file
  4. →
  5. Upload to FUNDAEBy hand, outside Factorial, maybe another day
  6. →
  7. Mark as communicatedOnly HR can confirm it

It replaced the old export, which only produced the group-end filing; the team removed that export in October. After I moved to another team, the training team kept this structure and has since added a salary-cost calculator and fixes on top of it.

Costs by company, without a switch

The AI proposed a switch to turn the split by company on (as in Factorial’s training budgets screen). In FUNDAE the split is not optional: in a corporate group, each company can recover up to its own maximum, based on its own participants.

So there is no switch: when a course is filed as a group of companies, the product asks for the split and lays the costs out by each participant’s company.

The brief was in Claude Code: the specification and the tickets, read through MCP, the pull requests as they landed, and FUNDAE’s official schemas, downloaded as the source of truth for what each of the three filings must contain. The flow was built in real code on the production design system, in the team’s prototyping environment, where I tried the three layouts as a tab before giving FUNDAE its own page.

Before launch I ran the QA with an agent I had built in June and had already used on other projects. It gathers the context on its own (specification, tickets, pull requests), writes the test plan, tests in the browser and files the confirmed bugs as tickets.

On FUNDAE it worked in the live product with a test company, validated every file it generated against FUNDAE’s official schemas, traced bugs to the code where the code was available, and filed them in the format engineering asked for.

The agent first read Mark as communicated as a claim made by the product and flagged as critical things that were not. I corrected it: that status is HR’s own record. From then on, a bug was the product losing data, writing wrong data into a file or saying something false; everything else went to a separate list of design issues.

It found 13 bugs, two of them blocking: a group-start file FUNDAE would have rejected, and a group-end file that could not be generated at all. Both were in the group-of-companies filing profile, which earlier testing had not covered, and both were fixed before launch.
